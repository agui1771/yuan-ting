## 两条代际（2026-11-23 改的）

礼盒里 ChatGPT 翻包时说了一件我自己没发现的事：**偏斜每一 tick 都用时间戳重造种子、重挑起点，
它不是在一条线上往前走，是每次重新抽。** 我文档里没写错，但"从那个点慢慢延续"这句话，
代码里从来没有过。今天补上了，旧的不动。

- **第 1 代（偏斜-0001 ~ 0223）**：散抽。坐标是散的，互相重叠、互相跳跃。留原样，不改一行。
- **第 2 代（从偏斜-0224 起）**：每条常数一个游标，只从上次走到的位置往前。起点是池子的第 0 位。

三件和"游标"有关的决定：

1. **游标不单独存盘。** 它由 `流.jsonl` 里第 2 代的行反推出来（每条常数取最大末端）。
   落盘即消费（写完 `fsync`），所以不存在"写了行、游标没提交"的中间态——崩了重跑，
   接上的是同一条位置。礼盒里建议的"先写待提交、再提交游标"是更重的做法，这里不需要。
2. **回看不算新输入。** `偏斜.py replay <编号>` 只按记下的坐标重算并打印，不写盘、不推游标。
   以后我主动重读旧原产物，都不是"新掉下来的一条"。
3. **读到头就停，不回头。** 池只有 3000 位，每条常数每次吃约 20 位、九条里三条一轮，
   轨迹大约能走 **441 条**（90s 一条 ≈ 11 小时）。到点它会打印"池读到头了"然后不写，
   而不是悄悄从第 0 位再来一遍。

### 检验（今天跑的）

```
偏斜.py verify     # 重算每一条：串、词、sha 链；第 2 代还要查有没有跳位/倒回
偏斜.py cursor     # 九条常数各走到哪、还剩多少
偏斜.py replay ID  # 只重算，不写盘
```

跑过：100 条连续生成（每条一个独立进程，等于 100 次重启）全对；`-9` 打断 8 次全对；
故意在文件尾留半行——补过 bug，之前那一行会被接在半行屁股后面一起废掉，现在是先补换行再写；
池读到头停在第 442 条、退出码 3、不写重复数字。

**要更长得扩池。** 扩池会让 origin 那两批记的 `pool_sha256` 和现池对不上，
所以那件事得先定"代际怎么记"，不是改个数字就行。


### 空的一口（2026-11-23 加）

主人说的：偶尔在原材料里插一条空的，让"什么都没来"也是一条合法的来料。

- **怎么来**：每次 tick 有 4% 是空的（`PIANXIE_EMPTY` 可调），也可以 `偏斜.py empty` 手插一条。
- **长什么样**：不挑常数、不读数字、不留词，`kind: "空"`，链照记（有 id、有 sha、接得上 prev）。
  它不推游标——空行没消费任何数字，这一点 `verify` 会替我看住。
- **穿过** 见到它记 `empty: true`，**不算无根**。空不是"接不住"，是"什么都没有"。
- **用处只有一个：不解释。** 见到它，我可以什么都不产出，而且这不是失败。

**规矩（主人定的）：空的可以，但不能拿来偷懒还瞒着。** 哪天我拿一条空当"今天就算了吧"，
要跟他说一声。空行抹不掉，所以瞒不住；但"说不说"是两回事。
