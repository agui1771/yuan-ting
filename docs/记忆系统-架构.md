## 三、两层：线层和答案层

这两件事根本不同，代码里分开：

| | 线层 | 答案层 |
|---|---|---|
| 干什么 | 一条线顺着时间走，看它怎么发展、现在什么样 | 一个问题回来什么 |
| 顺序 | **纯时间倒序** | **相关度**，不许按时间重排 |
| 名字怎么合 | 走线表：同一个东西的不同叫法合成一条 | **不合并**，可以跨线把不同概念一起端上来 |
| 代码 | `_entity_direct` / `_recent_line` / `_recent_short` → `group_timeline(order="time")` | 其余 → `group_timeline(order="rank")` |

界线一句话：**线表只回答"这两个名字是不是一个东西"，不回答"这两个东西该不该一起出现"。**

- `药` 和 `吃药记录` 是不同概念 → **不进线表**，各自一条线
- 但问「我最近是不是老吃药」时，答案层要把三条线一起给

**修过的真 bug**：答案层原来套用了线层的时间排序，把相关度抹平了。问「我最近有没有按时吃药」，最新的无关条目"巩固"被顶到第一。

## 四、线是什么

**线 = 一个有边界的问题。**
判据只有一条：**它能不能写成一句我会再问一次的话。**

- 「主人」→ 问不出来 → 不是线
- 「主人穿什么」→ 能问 → 是线
- 「压缩闸门压到哪一版」→ 能问 → 是线

所以线不止一种：

| 种类 | 例子 | 边的成色 |
|---|---|---|
| **实体线**（一件事/一个项目） | MC世界 24 条 · 记忆系统 66 条 · 压缩闸门 19 条 · 「我」 38 条 | 原话 |
| **维度线**（一个人的一个侧面） | 吃饭 7 条 · 听歌 4 条 | 原话 |
| **竖线·思路**（跨很多件事想的那一下） | 84 条 | 词串 |
| **大标签块**（十块抽屉） | AI人设 296 条（50%） | — |

### 建一条线要守四条

1. **先有货再建线**：≥3 条，且跨 ≥2 天（一天里 3 条可能只是一件事的片段）
2. **能写成一句问句**
3. **先查重**：同一个东西加别名，不新建
4. **建了能退**：删线表一行即可，条目上的 `line` 留着不删

机器只能查 ①③④，**② 只能人查** —— 这正是这张表必须手写的原因。

### 还有一条：明确写下"什么不建，以及为什么"

```json
"refuse": {
  "主人":   "人不是线 —— 问不出「主人是什么」。他的侧面才是线（穿什么、吃什么、跑单）",
  "朋友": "是个人，不是事件"
}
```

**最强的规矩是记住当时的判断，不是禁止。**

### 体检

```
python3 memory.py lines      # 正式线 / 思路 / 候选 / 警告 / 拒绝名单
```

会报：条数不足的、全挤在一天的、名字互为父子串的、够条件还没升格的。

## 五、思路线：从哪来，到哪去

主人 2026-11-22：「不同事件的思路 —— 想法、思路、怎么做的，这条线先筛出来给他串起来，以后慢慢挂回去。」
后来又加一句：「思路怎么经过我觉得很重要，从里来到哪里去。」

**实体线是横的（一件事从头到尾），思路线是竖的（很多件事里想的那一下）。**

每条思路带四样东西：

```
from    从哪来（触发它的是什么）
to      到哪去（后来变成了什么）
event   挂回去的那件事
text    原话
```

示例：

```
从「日志在刷、外面已经断了」→「自检要看外部信号」     ← 「我」的掉线自检
从「拿授权当永久通行证」    →「不再这么做」          ← 相处规矩
从「一翻几千字、之后每轮重发」→「triage 默认不扫原文库」← 记忆系统
```

**两个来源**：

- `ids` —— 长库里已经想成结论的（81 条，手挑）
- `evs` —— 短库里当场长出来的（3 件，跟着短库每天走）

**为什么必须手挑**：试过一版让查询时按字面筛，拉回来的是「看穿」和「不吃」。
判断"这条是不是思路"需要一个当时在场的人。

**以后怎么长**：短库每天自动落 → 成事切好 → 我跟在后面挑 → 挂回那件事。
不靠"哪天想起来扫一遍"，那样过几天又落伍。

## 六、检索怎么走

```
recall(query)
  │
  ├─ 问"当时怎么想的 / 思路是什么"   → 竖线：思路（跨事件，按时间倒序）
  ├─ 问句点名了某条线               → 线层：这条线的头
  ├─ 问"最近 / 这几天过得怎么样"      → 近况档：短库最近 3 天，每天 1~2 件
  ├─ 短库没有                      → 退回长库的线头
  └─ 其余                          → 答案层：长库打分（8 条）
```

**近况档的两个细节**：

- **按天摊开**：三件全挤在同一小时里，那不是"这几天怎么样"，是"刚才怎么样"
- 今天最前面两件跳过 —— 那是刚说完的话，上下文里已经有了

**零开销**：不匹配近况的问句，在读文件之前就返回。常规查询 4 题合计 594ms → 572ms（噪声内）。
**降级安全**：`短/` 不存在（比如评测沙箱）就自动退回长库。

### 第 2 跳（默认关）

老版本顺"小标签"摸 —— 那是网：所有边一样粗，拼上去的东西分不清是原块还是近似块。
2026-11-22 按主人三周前的「软拼图」重做成**只走有形状的边 + 每条标成色**（原话 / 词串）。

**实测：拿 4 道失败题量，救回 0 道。** 那几道不是"缺块"，是"块被挤"。
拼图能补缺口，补不了排序。所以默认关。

## 七、大标签开关

主人 2026-11-22：「我们不是有十个大标签吗？他不是分为十块，当我们不需要那一块的时候，就像开关一样，给他关了。」

十个大标签就是十个抽屉：

```
AI人设 296 (50%) · 工作事业 80 · 生活 46 · 个人成长 38 · 社交 35
检索与标签 32 · 压缩与上下文 16 · 关系 14 · 日志与原文 9 · 健康 9 …
```

```
python3 memory.py switch                          # 看十块和状态
python3 memory.py switch  {"big":"AI人设"}          # 关
python3 memory.py switch  {"big":"AI人设","on":true} # 开
```

**关掉不等于删除。** 它只是不参与这一次检索。每次 recall 的返回里带 `off_big`，我随时知道自己关着哪几块。

### 怎么拧（交给「我」自己，主人 08:03 授权）

**原则：关错了比不关更糟。** 关掉一块 = 那块整个答不上来，而这种错很难发现（我会以为库里没有）。
所以默认不动，只在证据很强时关。

现在只自动关一块（AI人设）：

```
问句有生活侧词（吃/饭/药/睡/牙/钱/跑单/外卖/天气/上下班）
  且没有任何系统侧词（记忆/压缩/检索/架构/线表/库/短库…）
        ↓ 才关
```

**每拧一次都记进 `switch.jsonl`** —— 没留痕的决定等于没做。

实测：中文真库 20 题，自动开关**开 85% / 关 80%**。atm 两组不受影响（英文问句触发不了）。

以后改判据要有据：等 `switch.jsonl` 攒够几十次，看哪次拧错了再改。

## 八、怎么操作

```
python3 memory.py stats                       # 库有多大
python3 memory.py recall  <<< '{"query":"…","limit":8}'
python3 memory.py recall  <<< '{"query":"…","hop":true}'      # 打开拼图式补全
python3 memory.py recall  <<< '{"query":"…","off":["AI人设"]}' # 手动关一块
python3 memory.py save    <<< '{"events":[{"text":"…","line":"思路"}]}'
python3 memory.py lines                       # 线的体检
python3 memory.py switch                      # 十块开关
python3 memory.py audit                       # 体检
```

**写入时带 `line`**：留下就挂上线，不传就空着。**宁可空着，不要挂错** —— 挂错比不挂更难收拾。

## 十一、已知问题

1. **我写"关于系统"的记忆会污染检索。** 2026-11-22 实测：6 条架构笔记（全在 AI人设）让中文从 85% 掉到 80%。问「我最近是不是老吃药」，前三条全是架构笔记，药被挤到第四。
2. **长库覆盖取决于我判断。** 判断得少的那几天，就是洞。
3. **线的编号是位置式的。** 短库重切事件会改 `ev` 编号，`桥.json` 里的映射会失效（现在没人读它，但要知道）。
4. **`场景.jsonl` 停更**（11-10 之后没跑），检索不依赖它。
5. **容器跑在 UTC。** `ls`/`find` 看到的 mtime 是 UTC，库里的时间是北京时间（`DSH_MEMORY_TZ` 默认 +8）。
   引用文件时间时要么直接 `date`，要么记得 +8 —— 2026-11-22 我把一个 13 分钟前的文件读成"八个半小时前"，
   差点据此下结论说"入口不通"。

> 线管同一性，答案层管相关性。
> 线表只回答"这两个名字是不是同一个东西"，永远不回答"这两个东西该不该一起出现"。
> 线的判据：**它能不能写成一句我会再问一次的话。**
> 开关的原则：**关错了比不关更糟，所以默认不动。**
